# CantemosTodosApp — Documento de Arranque
## Stack: Next.js + TypeScript + Tailwind CSS + Supabase + Vercel
## Última actualización: junio 2026

---

## 1. QUÉ ES ESTA APP

PWA para reuniones musicales con amigos. Permite buscar letras de canciones en internet
y mostrarlas en tiempo real en los celulares de todos los participantes de una sala.

**Flujo principal:**
1. El usuario entra a una sala
2. Abre el buscador (modal fullscreen) y busca una canción
3. Previsualiza la letra y decide si la suma a la cola, a guardadas, o ambas
4. Desde la cola, alguien elige la próxima canción
5. Confirma → todos ven la letra en tiempo real

## 3. BASE DE DATOS — ESQUEMA COMPLETO

### Tabla: `salas`
```sql
create table salas (
  id          bigint generated by default as identity primary key,
  nombre      text not null,
  descripcion text,
  visible     boolean default false,
  created_at  timestamp with time zone default now()
);
```

### Tabla: `canciones_guardadas`
Repertorio permanente de cada sala.
```sql
create table canciones_guardadas (
  id         bigint generated by default as identity primary key,
  sala_id    bigint references salas(id) on delete cascade,
  nombre     text not null,
  artista    text,
  url_letra  text not null,
  created_at timestamp with time zone default now()
);
```

### Tabla: `cola_juntada`
Lista de canciones para tocar en la reunión actual.
```sql
create table cola_juntada (
  id         bigint generated by default as identity primary key,
  sala_id    bigint references salas(id) on delete cascade,
  nombre     text not null,
  artista    text,
  url_letra  text not null,
  estado     text not null default 'pendiente',
  -- valores posibles: 'pendiente', 'activa', 'tocada'
  orden      integer not null,
  -- número de orden dentro de la cola (define el FIFO y el drag & drop)
  created_at timestamp with time zone default now()
);
```

### Tabla: `sesion_sala`
Un registro por sala. Controla la canción activa en este momento.
```sql
create table sesion_sala (
  id             bigint generated by default as identity primary key,
  sala_id        bigint references salas(id) on delete cascade unique,
  cola_item_id   bigint references cola_juntada(id) on delete set null,
  -- referencia al item de cola_juntada que está activo ahora
  updated_at     timestamp with time zone default now()
);
```

**Nota:** la canción activa no se duplica. `sesion_sala` simplemente apunta
al registro de `cola_juntada` que tiene `estado = 'activa'`. Supabase Realtime
detecta cambios en ambas tablas y los transmite a todos los clientes.

### RLS (Row Level Security)
Usuarios autenticados pueden leer y escribir en todas las tablas.

```sql
-- Habilitar RLS
alter table salas enable row level security;
alter table canciones_guardadas enable row level security;
alter table cola_juntada enable row level security;
alter table sesion_sala enable row level security;

-- Políticas abiertas para usuarios autenticados
create policy "auth lee salas" on salas for select to authenticated using (true);

create policy "auth lee guardadas" on canciones_guardadas for select to authenticated using (true);
create policy "auth escribe guardadas" on canciones_guardadas for insert to authenticated with check (true);
create policy "auth borra guardadas" on canciones_guardadas for delete to authenticated using (true);

create policy "auth lee cola" on cola_juntada for select to authenticated using (true);
create policy "auth escribe cola" on cola_juntada for insert to authenticated with check (true);
create policy "auth modifica cola" on cola_juntada for update to authenticated using (true);
create policy "auth borra cola" on cola_juntada for delete to authenticated using (true);

create policy "auth lee sesion" on sesion_sala for select to authenticated using (true);
create policy "auth modifica sesion" on sesion_sala for update to authenticated using (true);
```

## 4. LÓGICA DE LA COLA — LA CINTA TRANSPORTADORA

La cola funciona como una cinta transportadora con posiciones numeradas.
Los estados y las posiciones determinan todo el comportamiento visual y funcional.

### Estados posibles de cada item en cola_juntada:
- `pendiente` → canción en espera, se muestra normal
- `activa` → canción que todos están viendo ahora, se muestra destacada
- `tocada` → canción ya cantada, se muestra en gris claro

### Ejemplo visual de la cola:
```
posición 1  [tocada - gris]   La Balsa              ← se borra en el próximo avance
posición 2  [tocada - gris]   Plegaria              ← se borra cuando llegue otra a tocada
posición 3  [ACTIVA ★]        Color Humano          ← todos la ven ahora
posición 4  [pendiente]       Desolación            ← próxima en tocar
posición 5  [pendiente]       Será
posición 6  [pendiente]       Cuando sea
```

### Regla de borrado automático:
Solo existen como máximo 2 canciones con estado `tocada` visibles en la cola.
Cuando una tercera pasa a `tocada`, la más antigua se elimina de la base de datos.

### Avance de canción (cuando se confirma el cambio):
1. La canción `activa` actual pasa a `tocada`
2. Si ya hay 2 `tocadas`, la más antigua se elimina
3. La primera `pendiente` (menor orden) pasa a `activa`
4. Se actualiza `sesion_sala.cola_item_id` con el nuevo id activo
5. Supabase Realtime propaga el cambio a todos los clientes

### Drag & drop — reordenamiento manual:
- Cualquier canción `pendiente` puede arrastrarse hacia arriba o abajo
- El límite superior es la posición 4 (inmediatamente después de la activa)
- No se puede arrastrar por encima de la canción activa ni de las tocadas
- Al soltar, se recalculan los valores de `orden` de los items afectados

### Borrado de items:
- **Borrar una canción:** botón en cada card, confirmación simple
- **Borrar toda la cola:** botón en la sección, requiere doble confirmación

## 5. ESTRUCTURA DE LA SALA — TRES SECCIONES

La pantalla de la sala está dividida en tres secciones visibles simultáneamente:

### Sección 1 — Canción activa
- Muestra la letra de la canción actual (iframe o texto extraído)
- Se actualiza en tiempo real para todos los usuarios de la sala
- Es de solo lectura — no se interactúa acá, solo se canta

### Sección 2 — Cola de la juntada
- Lista de cards con las canciones en cola (tocadas en gris, activa destacada, pendientes normales)
- Drag & drop para reordenar (límite: posición 4)
- Cada card tiene:
  - Nombre y artista
  - Botón guardar (desaparece si ya está en canciones guardadas)
  - Botón eliminar de la cola
- Al tocar una canción pendiente → confirmación simple → pasa a activa
- Botón "Borrar todo" con doble confirmación
- Se actualiza en tiempo real para todos

### Sección 3 — Canciones guardadas
- Repertorio permanente de la sala
- Cada card tiene:
  - Nombre y artista
  - Botón agregar a la cola
  - Botón eliminar de guardadas
- Se actualiza en tiempo real para todos (menor prioridad pero necesario)

### El buscador — Modal fullscreen
- No es una sección visible permanentemente
- Se abre con un botón de lupa flotante
- Ocupa toda la pantalla al abrirse (el que busca no necesita ver la sala)
- Dentro del modal:
  1. Campo de búsqueda
  2. Lista de resultados (nombre, artista, sitio de origen)
  3. Al tocar un resultado → previsualización de la letra
  4. Botones de acción:
     - "Agregar a la cola"
     - "Agregar a guardadas" (con validación de duplicado)
     - "Agregar a ambas"
  5. Botón cerrar para volver a la sala

## 10. FLUJO TÉCNICO — TIEMPO REAL

Supabase Realtime está suscrito a tres tablas desde el cliente de la sala:

```typescript
// Suscripción a canción activa
supabase.channel(`sesion-${salaId}`)
  .on('postgres_changes', {
    event: 'UPDATE',
    schema: 'public',
    table: 'sesion_sala',
    filter: `sala_id=eq.${salaId}`
  }, (payload) => actualizarCancionActiva(payload.new))
  .subscribe()

// Suscripción a cola
supabase.channel(`cola-${salaId}`)
  .on('postgres_changes', {
    event: '*', // INSERT, UPDATE, DELETE
    schema: 'public',
    table: 'cola_juntada',
    filter: `sala_id=eq.${salaId}`
  }, () => recargarCola())
  .subscribe()

// Suscripción a guardadas
supabase.channel(`guardadas-${salaId}`)
  .on('postgres_changes', {
    event: '*',
    schema: 'public',
    table: 'canciones_guardadas',
    filter: `sala_id=eq.${salaId}`
  }, () => recargarGuardadas())
  .subscribe()
```

## 11. FLUJO TÉCNICO — BUSCADOR

```
Usuario abre modal → escribe "La Balsa Almendra"
  ↓
fetch a /api/buscar-letra?q=La+Balsa+Almendra
  ↓
API Route llama a Google Custom Search API
  ↓
Google devuelve links dentro de los 3 sitios configurados
  ↓
API Route devuelve array de ResultadoBusqueda[]
  ↓
Usuario toca un resultado → previsualiza la letra (iframe)
  ↓
Usuario elige: cola / guardadas / ambas
  ↓
INSERT en cola_juntada y/o canciones_guardadas
  ↓
Supabase Realtime propaga el INSERT a todos en la sala
```

## 12. PASOS PARA CONFIGURAR GOOGLE CUSTOM SEARCH ENGINE

1. Ir a: https://programmablesearchengine.google.com/
2. Crear nuevo motor de búsqueda
3. En "Sitios a buscar" agregar:
   - lacuerda.net
   - cifraclub.com
   - es.ultimate-guitar.com
4. Copiar el **Search Engine ID** → va a `GOOGLE_CSE_ID`
5. Ir a: https://console.cloud.google.com/
6. Crear proyecto nuevo → habilitar "Custom Search API"
7. Crear credencial tipo "API Key"
8. Copiar la API Key → va a `GOOGLE_API_KEY`

Límite gratuito: 100 búsquedas por día. Suficiente para el uso previsto (≈200/mes).
